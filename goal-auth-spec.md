2. Делай по фазам (список ниже). После каждой фазы: перечитай свой диф, прогони сборку/тесты, отметь пункты плана, честно напиши что сделано и что осталось.

4. Безопасность не обсуждается: пароли только хэшировать (bcrypt/argon2), никогда не хранить и не логировать в открытом виде. Секреты — только через env, НИКОГДА не хардкодить и не коммитить. Все вводы валидировать на бэке.
5. Проектируй на вырост: полей у машины и достижений станет больше — схемы фида и достижений должны расширяться без переписывания.
6. В конце обнови README.md и DEPLOY.md (новые env, новые миграции, бакет Storage, запуск Telegram-воркера) и напиши краткую инструкцию «что мне вписать в env / настроить в Supabase».
7. Пиши в стиле существующего кода (те же соглашения, комментарии по-русски, тот же паттерн роутов и миграций NNN_*.sql).

## КОНТЕКСТ ПРОЕКТА (факты, не выдумывай)
- Backend: Node.js + Express + PostgreSQL. Вход backend/src/index.js, роуты backend/src/routes/, БД через backend/src/db/client.js (query()). Сейчас весь /api закрыт одним общим x-api-key.
- Frontend: Vite + vanilla JS. Запросы через apiFetch() в frontend/src/main.js (шлёт x-api-key). Роутинг по hash: #/ — поиск, #/car/:id — страница машины (frontend/src/carPage.js). Стили frontend/src/style.css.
- БД: миграции db/migrations/NNN_*.sql по порядку + сгенерированный db/supabase_setup.sql. В таблице cars УЖЕ есть колонка created_by text (используй для «кто добавил»).
- Userscript-калькулятор: корневой .user.js — СОБИРАЕМЫЙ артефакт, руками не править. Логику править в shared/ и userscript/src/oil-calculator/app.js, потом npm run build:userscript. Кнопка «📤 Отправить отчёт» делает POST /api/cars с x-api-key через GM_xmlhttpRequest.
- Прод: Postgres на Supabase, backend на Railway, frontend на Vercel. Картинки — через Supabase Storage.

## ЧТО ПОСТРОИТЬ

### A. Аутентификация и сессии
- Таблица users: id, display_name (рус/лат), login (уникальный), password_hash, role ('user'|'mod'|'admin'), avatar (URL в Supabase Storage; если пусто — дефолтная шаблонная аватарка), created_at.
- Таблица sessions (или подписанные токены) с created_at; клиент хранит токен и шлёт Authorization: Bearer … ДОПОЛНИТЕЛЬНО к x-api-key. x-api-key оставить как грубый гейт, поверх — личность пользователя по сессии.
- Эндпоинты: POST /api/auth/login, POST /api/auth/register (заявка, блок B), POST /api/auth/logout, GET /api/auth/me.
- ГЕЙТ ДОСТУПА: без валидной сессии на сайте не видно НИЧЕГО, кроме экрана входа/регистрации. Поиск, страница машины, фид, топ — только для залогиненных. При старте, если сессии нет/протухла — форма «логин + пароль» и кнопка «Регистрация».
- АВТОВЫХОД В ПОЛНОЧЬ ПО МСК: с первой минутой новых суток по Москве (UTC+3) сессии недействительны у всех. Без крона: middleware считает «последнюю наступившую полночь МСК» и отклоняет сессию с created_at < неё (→ 401, разлогин). Это же заставляет юзерскрипт заново спрашивать логин на следующий день.

### B. Регистрация через заявку + Telegram-админка
- Форма: «Отображаемое имя» (рус/лат), «Логин для входа», «Пароль», кнопка «Отправить заявку».
- Заявка → pending (registration_requests: display_name, login, password_hash, status, created_at, expires_at) и уходит мне в Telegram админу ID 691442300 (env ADMIN_TELEGRAM_ID, дефолт 691442300).
- В сообщении бота видно: когда пришла, какое имя и логин. Под сообщением inline-кнопки «✅ Accept» / «❌ Decline». Accept создаёт пользователя, Decline отклоняет.
- ЖИЗНЬ ЗАЯВКИ 30 МИНУТ: после expires_at заявка мертва (accept не срабатывает, статус → expired). Дубли логина не допускать.
- Бот — отдельный воркер/процесс в backend (long-polling getUpdates). Токен только из env TELEGRAM_BOT_TOKEN.

### C. Роли, модерация и управление через Telegram
- Перманентный ЗЕЛЁНЫЙ префикс «mod» перед ником, тултип при наведении «модератор». Спроектируй расширяемо под другие роли/префиксы.
- В Telegram-админке рабочие:
  - Поиск пользователей + управление: «Забанить» (полностью удаляет профиль), «Поменять ник», «Сделать модератором / Снять модератора».
  - Поиск машин + полное удаление машины из БД.
  - Передача доступа к админке: указываю Telegram user id — бот начинает слушать команды и от него (список админов бота хранить в БД/конфиг-таблице, не только в env).

### D. Главная страница после входа
- Как сейчас: обычный поиск, UX не ломать.
- Слева сверху кружок с шаблонной аватаркой; клик открывает профиль.
- Рядом кнопка с иконкой звёздочки «Топ»: топ всех пользователей по числу добавленных машин. 1-е место ПЕРЕЛИВАЕТСЯ золотым (блеск-анимация), остальные обычные.

### E. Страница профиля (отдельная страница, можно фулскрин)
- По центру аватар, под ним ник — оба КЛИКАБЕЛЬНЫ и редактируемы.
- Аватар меняется ЗАГРУЗКОЙ ФАЙЛА в Supabase Storage (bucket 'avatars', публичный URL в users.avatar; лимит размера/типа на бэке — только изображения). Нет файла — дефолтная картинка. Ник (display_name) меняется тут же.
- Статистика в ряд: «Добавлено машин», «Отредактировано машин».
- Поле «Достижения»: горизонтальный фид карточек «картинка → текст → дата», при наведении — условия выполнения. Реальных достижений НЕ добавлять — готовый пустой расширяемый фид-заглушка.
- Кнопка «Выйти».

### F. Фид изменений/добавлений — ТОЛЬКО на странице машины, по конкретной машине
- Фид живёт НА СТРАНИЦЕ МАШИНЫ (frontend/src/carPage.js), НЕ на главной. Показывает только события ЭТОЙ машины (по car_id), хронологически.
- Плашки «Машина добавлена пользователем {ник}» / «Отредактировано пользователем {ник}». СЛЕВА крупная аватарка автора. Один дизайн, разный цвет (добавление/редактирование).
- Если created_by пуст — плашку добавления не показывать. Дальше фид этой машины нормально пополняется.
- Таблица car_events (id, car_id, user_id, type 'added'|'edited', comment text, changed_fields jsonb, created_at). Пишется при POST /api/cars (added) и PATCH /api/cars/:id (edited). На вырост: полей станет больше — changed_fields это переваривает.
- Эндпоинт GET /api/cars/:id/events.
- При сохранении правок — окно «Опишите, почему изменили?» + «Сохранить» (можно пусто → просто «Отредактировано пользователем {ник}»).
- Клик по плашке правки открывает окно: какие поля изменены (было/стало) + комментарий.

### G. Удаление машины модератором
- У роли mod на странице машины, кроме «Нашли ошибку?», кнопка «Удалить машину».
- Клик → модальное предупреждение: машина будет удалена ПОЛНОСТЬЮ И БЕЗВОЗВРАТНО, с подтверждением.
- Бэкенд: DELETE /api/cars/:id, только роль mod/admin (проверка на сервере, не только в UI).

### H. Юзерскрипт-калькулятор (привязка отправки к сессии)
- Кнопка «📤 Отправить отчёт» привязана к сессии. При отправке, если валидной сессии нет — спросить логин/пароль, залогиниться (POST /api/auth/login), запомнить токен (GM_setValue), слать отчёт с ним.
- created_by = залогиненный пользователь (для статистики и фида).
- Полночь МСК: на следующий день токен протух → снова спросить логин. Править shared/ и userscript/src/oil-calculator/app.js (при необходимости хост бэкенда в @connect header.txt), затем npm run build:userscript.
