# Краулер фида кандидатов

Автозаполнение базы: скрипт «слизывает» данные с **MANN-FILTER** (три артикула
фильтров + каноничное имя марки/модели с кузовом в скобках) и с **Motul
Lubricant Advisor** (объёмы жидкостей по агрегатам), склеивает черновик и кладёт
его в фид кандидатов на сайте — вкладка **«Добавить машины»**. Дальше оператор
листает фид, правит карточку и жмёт «Добавить в БД» либо «Удалить».

Ничего не пишется в боевую таблицу `cars` напрямую — только в очередь
`car_candidates`. Живые данные появляются лишь после ручного аппрува.

## Что откуда берётся

| Поле | Источник | Примечание |
|------|----------|------------|
| Марка, модель, **кузов (generation)** | MANN | кузов «(E90)», «(W204)» → `generation` |
| вф / мф / сф (3 фильтра) | MANN | логика из юзерскрипта «Скопировать 3 артикула»: только доступные и не устаревшие, салонный CU > CUK, FP игнор |
| Объёмы ДВС/АКПП/МКПП/раздатки/дифов | Motul | порт `parseMotulAdvice` из калькулятора |
| Допуска масла | — | Motul их не даёт; добавляет оператор (ROLF/Ravenol) |

`match_quality` в карточке: `good` (все 3 фильтра + объёмы), `partial`,
`no_filters` (MANN не отдал фильтры), `weak` (модель не распозналась).

## Установка и запуск

```bash
cd tools/crawler
npm install                       # ставит playwright и сам скачивает Chromium
cp config.example.json config.json
#   впиши apiBase и apiKey (тот же X-API-KEY, что у бэкенда на Render)

# СНАЧАЛА тюнинг-прогон на 1–2 машинах с видимым браузером и без записи:
node crawl.mjs --limit 2 --headful --dry-run

# когда селекторы подтверждены — боевой прогон партией:
node crawl.mjs --limit 50 --delay 4000
```

Флаги:

- `--limit N` — сколько машин за прогон (по умолчанию 50; «партиями, чтобы не
  ронять сайты»).
- `--delay MS` — базовая пауза между машинами (по умолчанию 4000 мс, с джиттером).
- `--headful` — показать браузер (для отладки селекторов).
- `--dry-run` — не писать в фид, только печатать, что нашлось.
- `--seeds path.json` — свой список машин.

## Дубли и резюме

- Перед заливкой краулер спрашивает бэкенд `POST /api/candidates/known`, какие
  машины уже есть (в `cars` или в очереди, **включая отклонённые**), и не
  предлагает их повторно — «по второму кругу одну и ту же машину» не увидишь.
- Прогресс по seed-списку пишется в `.progress.json`. Повторный запуск
  продолжает с места остановки. Чтобы начать заново — удали этот файл.

## Rate-limit (важно)

Опасение «MANN пошлёт с таким количеством запросов» — обоснованное, поэтому по
умолчанию скрипт идёт медленно: одна машина за ~8–10 секунд (MANN + Motul +
паузы с джиттером), партиями по 50. Не убирай задержки и не гоняй в несколько
потоков. Полный каталог — это надолго; начинай с приоритетного `seeds/starter.json`
и расширяй список (например, выгрузкой популярных моделей из SPOT CRM).

## Точки тюнинга (сверить на первом `--headful`-прогоне)

Логика **парсинга** портирована из рабочих юзерскриптов и стабильна. А вот
**навигацию** по живым сайтам надо один раз подтвердить — сайты меняют вёрстку:

1. `src/motul.js` — селектор автоподсказки умного поиска
   (`.ui-autocomplete li` и т.п.) и переход на страницу advice.
2. `src/mann.js` — `buildSearchUrl()` (актуальный путь и имена параметров
   каталога) и селектор заголовка выбранной машины (`vehicleTitle`).

Эти два места помечены в коде комментариями «точка тюнинга». Всё остальное
(извлечение фильтров, разбор объёмов, дедуп, резюме, заливка) — готово.

> Примечание про песочницу Claude: headless-браузер в облачной песочнице не
> может достучаться до внешних сайтов через egress-прокси (ERR_CONNECTION_RESET),
> поэтому финальный тюнинг навигации делается на машине с обычной сетью
> (твой ПК или CI-раннер). Приёмная часть (фид, бэкенд, дедуп) полностью
> собрана и протестирована.
