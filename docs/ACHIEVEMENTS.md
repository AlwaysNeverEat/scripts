# Как добавить новую ачивку (чеклист)

Система устроена так, что новая ачивка — это **код + картинка, без миграций БД**.
В БД (`user_achievements`) хранится только факт получения (`achievement_id`,
`unlocked_at`, `notified_at`); названия, описания, пороги и картинки живут в коде.

## Чеклист

1. **Определение** — `backend/src/achievements/achievements.js`, массив `ACHIEVEMENTS`:
   ```js
   { id: 'my_achievement', title: '…', description: '…', metric: 'added', threshold: 5 }
   ```
   - `id` — snake_case, навсегда (уже выданные строки в БД ссылаются на него);
   - `metric` — одна из метрик `computeMetrics()`: `added` (добавленные машины),
     `edited` (отредактированные МАШИНЫ, не правки — DISTINCT car_id),
     `registered` (константа 1 — есть у всех). Новая метрика = новое поле в
     `computeMetrics()`, считающееся ИЗ ИСТОЧНИКА ПРАВДЫ (car_events и т.п.),
     а не инкрементом.

2. **Картинка** — PNG 256×256 в `frontend/src/assets/ach-<id через дефис>.png`
   (исходники 1512×1512 ужимать, иначе бандл распухает). Картинки НЕ грузятся
   в БД и не лежат в Storage — они бандлятся Vite вместе с фронтом.

3. **Карта иконок** — `frontend/src/achievements.js`, объект `ICONS`:
   `import` картинки + строка `my_achievement: achMyAchievement`.
   Без записи в ICONS карточка покажет заглушку 🏆.

4. **Партиклы (опционально)** — `frontend/src/achievementParticles.js`,
   объект `PARTICLE_EFFECTS`. Эффект получает `(layer, k)`, все координаты
   макета (240px) умножать на `k`.

5. **Тесты** — `backend/src/achievements/achievements.test.js`: порог/название
   через `diffAchievements`/`achievementById`. Запуск: `npm run test:backend`.

## Что НЕЛЬЗЯ ломать

- **Никаких инкрементов счётчиков.** Начисление/отзыв — только через
  `syncAchievements()`, который каждый раз полностью пересчитывает метрики и
  приводит ачивки в соответствие (докидывает и ЗАБИРАЕТ). Ачивки отзываемые:
  переназначение/удаление машины уменьшает счётчик — ступень снимается.
- **Синк уже дёргается везде, где меняются счётчики**: POST/PATCH/DELETE
  машин, /assign, /bulk-assign, и самолечащийся синк в
  GET /profile/achievements/pending (каждый вход на сайт). Новую ачивку на
  СУЩЕСТВУЮЩЕЙ метрике никуда подключать не надо — её довыдаст pending-синк.
- **Тосты**: `notified_at` в БД (NULL = тост не показан). Фронт сам опросит
  pending и покажет тост — руками ничего не делать.
- Существующим пользователям ачивка доначислится сама при первом визите
  после деплоя (pending-синк) — бэкфилл SQL нужен только если хочется
  красивую дату `unlocked_at` задним числом.
