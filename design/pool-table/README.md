# Текстуры пасхалки «Бильярд» — исходник и раскладка

Всё пришло **одним листом** `8ball_textures.zip` → PNG 1536×1024 с готовым
альфа-каналом (ничего кеить не пришлось — элементы уже вырезаны). Из него
нарезаны три картинки, четвёртая не используется.

## Что где на листе

Координаты — по альфа-каналу, замерены скриптом, а не на глаз.

| Элемент | Область на листе | Размер | Куда лёг |
|---|---|---|---|
| Сукно | 24,99 – 697,512 | 673×413 | `frontend/src/assets/pool-cloth.webp` |
| Борт (с лузами) | 721,89 – 1512,524 | 791×435 | `frontend/src/assets/pool-rail.webp` |
| Луза отдельно | 116,616 – 417,918 | 302×303 | **не используется** |
| Кий | 486,790 – 1492,839 | 1006×49 | `frontend/src/assets/pool-cue.webp` |

Отдельная луза не нужна: **лузы нарисованы в самом борте**, все шесть. Класть
поверх ещё по кругу означало бы рисовать лузу дважды и ловить расхождение в пару
пикселей на каждой.

Формат — WebP, качество 88: PNG тех же трёх картинок весит 1.2 МБ, WebP — 181 КБ
(сукно 121, борт 45, кий 16). Прозрачность WebP держит, а чанк игры и так грузится
только по клику в меню.

Пересобрать из листа:

```bash
python3 - <<'PY'
from PIL import Image
im = Image.open('8ball_sheet.png').convert('RGBA')
for name, box in {
    'pool-cloth': (24, 99, 697, 512),
    'pool-rail':  (721, 89, 1512, 524),
    'pool-cue':   (486, 790, 1492, 839),
}.items():
    im.crop(box).save(f'frontend/src/assets/{name}.webp', quality=88, method=6)
PY
```

## Главное число: внутренний прямоугольник борта

Весь стол выравнивается ОДНИМ действием — внутренний прямоугольник картинки
борта натягивается на игровое поле. Тогда нарисованные лузы сами встают в шесть
игровых точек, и подгонять ничего не надо.

В картинке борта 791×435 этот прямоугольник — **60,60 … 731,376** (672×317).
Отсюда в `frontend/src/pool.js` живёт

```js
const RAIL_IMG = { w: 791, h: 435, x: 60, y: 60, iw: 672, ih: 317 };
```

и из него же считаются отступы борта (RAIL_L/T/R/B) и размер холста. Толщина
борта получается ≈7 дюймов при поле 78×39 — руками она нигде не задана.

Пропорция внутреннего прямоугольника 2.12:1 против игровых 2:1 — борт слегка
растягивается по вертикали. На дереве шести процентов не видно, а лузы взамен
стоят точно там, где их ждёт физика.

Сукно рисуется **с запасом в 1.5 дюйма за края поля и уходит под борт**: у
внутренней кромки альфа сходит на нет не мгновенно, и по периметру оставался
тёмный шов.

## Луза: картинка задаёт физику, а не наоборот

Вырез средней лузы у самой кромки имеет полуширину **3.83 дюйма** (замер по
альфе: на 2 px выше кромки прозрачный участок 66 px при 0.1161 дюйма на пиксель).
Отсюда в `shared/pool.js`:

- `POCKET_MOUTH` = 3.825 — устье, внутри него борта для шара нет;
- `POCKET_R` = 2.7 — захват, ровно на радиус шара меньше.

Связь обязательна: тогда шар пропадает в тот момент, когда целиком вошёл в
нарисованную лузу. **Перерисуют борт с другими лузами — эти числа надо
пересчитать**, иначе игра начнёт отбивать шары от невидимого борта посреди
нарисованной лунки (ровно этим и болела первая версия).

Проверено перебором: шар, пущенный в угловую и в среднюю лузу с девяти углов и
трёх сил, падает во всех 54 случаях.

## Кий

На картинке лежит горизонтально, **наклейкой (тонким концом) ВПРАВО**. Код это
знает: правый край картинки ставится в точку касания с битком, тело уходит
влево, и всё поворачивается по направлению удара. Длина в игре — 40 дюймов,
толщина считается из пропорций картинки (1006×49).

Когда биток стоит у борта, кий уходит за край холста и обрезается — так и должно
быть: настоящий кий тоже торчит за стол.

## Чего в текстурах нет

**Шары остаются вёрсткой** — цветной круг с номером в белом кружке. На экране, где
шар размером в двадцать пикселей, это читается лучше любой фотографии.

Иконки игры для меню тоже нет — плитка пока рисует номера вёрсткой (поле `blank`
в `GAMES`). Если рисовать, то по правилам `design/game-icons/README.md`: 256×256.
