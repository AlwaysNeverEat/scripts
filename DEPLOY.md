# Деплой по бесплатному пути: Supabase + Render + GitHub Pages

Три части системы и где они живут:

| Часть | Хостинг | Бесплатно |
|-------|---------|-----------|
| PostgreSQL | Supabase | да (free tier) |
| Backend (Express API) | Render.com | да (засыпает после 15 мин простоя, первый запрос ждёт ~30–60 сек) |
| Сайт (статика) | GitHub Pages | да |

Порядок важен: база → backend → сайт → юзерскрипты.

---

## 1. Supabase (база + Storage) — ~10 минут

1. В проекте (`cars-db`) открой **SQL Editor**.
2. Прогони по очереди содержимое файлов из `db/migrations/`, каждый — отдельным
   запуском Run, по порядку номеров (`001` → `013`). Проще — один раз вставить
   целиком `db/supabase_setup.sql` (он уже собран из всех миграций по порядку).
3. Кнопка **Connect** (вверху) → вкладка **Session pooler** → скопируй URI вида
   `postgresql://postgres.xxxx:[PASSWORD]@aws-0-eu-west-1.pooler.supabase.com:5432/postgres`
   и подставь свой пароль от базы.
4. **Storage → New bucket** → имя `avatars` → **Public bucket: включить**
   (иначе аватарки не откроются с сайта). Больше ничего настраивать не нужно —
   запись в бакет идёт через service-role ключ из backend, не через клиента.
5. **Project Settings → API** → скопируй **Project URL** (→ `SUPABASE_URL`) и
   **service_role** ключ, НЕ anon (→ `SUPABASE_SERVICE_KEY`, шаг 2 ниже).

> Именно **Session pooler**, не Direct connection — прямое подключение у
> Supabase доступно только по IPv6, а Render ходит по IPv4.

## 2. Render (backend + Telegram-бот) — ~10 минут

Telegram-бот стартует в том же backend-процессе (не отдельный сервис) —
второй платный сервис на Render заводить не нужно.

1. [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint** →
   подключи GitHub-репозиторий `scripts` — Render сам найдёт `render.yaml`.
2. В настройках сервиса `cars-db-backend` → **Environment** заполни:
   - `DATABASE_URL` — URI из шага 1.3
   - `API_KEY` — придумай длинную случайную строку (это общий пароль API)
   - `CORS_ORIGINS` — `https://<твой-логин>.github.io`
   - `TELEGRAM_BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
     (`/newbot`, следуй подсказкам). Пусто — заявки на регистрацию будут
     копиться в БД, но никто не увидит кнопки Accept/Decline.
   - `ADMIN_TELEGRAM_ID` — твой Telegram user id (узнать у
     [@userinfobot](https://t.me/userinfobot)); дефолт `691442300`.
   - `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` — из шага 1.5.
3. Дождись деплоя, открой `https://<имя-сервиса>.onrender.com/health` —
   должно ответить `{"ok":true}`. Запомни этот URL.
4. **Важно**: напиши своему боту `/start` в Telegram хотя бы один раз —
   без этого Telegram не разрешает боту первым слать тебе сообщения, и
   уведомление о первой заявке на регистрацию до тебя не дойдёт.

## 3. GitHub Pages (сайт) — ~5 минут

1. Репозиторий → **Settings → Pages → Source: GitHub Actions**.
2. **Settings → Secrets and variables → Actions**:
   - вкладка **Variables** → `VITE_API_BASE` = URL backend'а с Render
     (например `https://cars-db-backend.onrender.com`, без слэша в конце)
   - вкладка **Secrets** → `VITE_API_KEY` = тот же `API_KEY`
3. Запусти workflow **Deploy site to GitHub Pages** (вкладка Actions → Run
   workflow) или просто запушь что-нибудь в `frontend/` в main.
4. Сайт появится на `https://<твой-логин>.github.io/scripts/`.

## 4. Юзерскрипты — переключить на прод

1. В `userscript/src/oil-calculator/app.js` и `userscript/src/notifier/app.js`
   поменяй константы:
   ```js
   const DB_API_BASE = 'https://cars-db-backend.onrender.com';
   const DB_API_KEY  = '<твой API_KEY>';
   const DB_SITE_URL = 'https://<твой-логин>.github.io/scripts';
   ```
   (в нотификаторе они называются `API_BASE` / `API_KEY` / `SITE_URL`)
2. В обоих `header.txt` замени `@connect localhost` на
   `@connect cars-db-backend.onrender.com` (свой хост Render).
3. Закоммить в main — Action пересоберёт `.user.js`, Tampermonkey у всех
   подтянет обновление сам.

## 5. Регистрация первого пользователя

Сайт и юзерскрипт теперь требуют аккаунт — без входа виден только экран
входа/регистрации.

1. Открой сайт → «Нет аккаунта? Регистрация» → заполни имя/логин/пароль →
   «Отправить заявку».
2. В Telegram придёт сообщение с кнопками **✅ Accept / ❌ Decline** (заявка
   живёт 30 минут — не тяни). Нажми Accept.
3. Вернись на сайт, войди новым логином/паролем.

## Проверка всего пути

1. Зарегистрируйся и войди (см. пункт 5 выше).
2. Открой машину на mann-filter.com, посчитай как обычно → «📤 Отправить отчёт»
   → юзерскрипт спросит логин/пароль (тот же аккаунт) → «Отправить».
3. Клик по ссылке в зелёном тосте → страница машины на
   `github.io/scripts/#/car/...` — внизу должна появиться плашка «Машина
   добавлена пользователем …» с твоей аватаркой.
4. На сайте набери в поиске «форд фокус» (или свою машину по-русски).
5. У коллеги с нотификатором на той же машине на Mann появится баннер
   «✓ эта машина уже рассчитана».
6. Кружок-аватарка слева сверху → профиль: смени ник, загрузи аватарку
   (должна лечь в Supabase Storage), проверь статистику.
7. Кнопка «⭐ Топ» → твой аккаунт должен быть в списке с числом добавленных
   машин (1-е место переливается золотым).

## Известные ограничения бесплатного плана

- Render засыпает: первый запрос после простоя ждёт ~30–60 сек (юзерскрипт
  покажет таймаут — просто повтори). Supabase free может ставить базу на
  паузу после недели без обращений — заходи в дашборд, жми Restore.
- API-ключ вшит в сборку сайта и юзерскрипта — это грубый гейт «свой/чужой»,
  а не секрет. Личность пользователя (кто добавил/отредактировал/что можно
  удалять) проверяется отдельным слоем — сессией поверх ключа, её подделать
  на клиенте нельзя.
- Сессии обнуляются в полночь по МСК для всех сразу — на следующий день сайт
  и юзерскрипт снова спросят логин. Это ожидаемое поведение, не баг.
